**비트웨이브에서 새로 추가한 것 (콜비즈엔 없던 것)**
- `.has-sub > .sub` — 드롭다운. 콜비즈는 1단 메뉴였지만 비트웨이브는 솔루션 8개라 필요
- `.nav-burger` + `.drawer` — 모바일 메뉴. 콜비즈는 860px 이하에서 메뉴를 **그냥 숨김**(`display:none`).
  항목이 적어서 가능했던 것. 비트웨이브는 메뉴가 많아 숨기면 못 씀
- `.cards3` — 3열 그리드
- `.lead`에 email/select/textarea 추가 — 기업 문의는 항목이 더 많음

## 5. 지켜야 할 규칙 (기존 작업에서 정해진 것)

1. **UI 이모지 금지.** AI로 만든 티가 남. 아이콘은 인라인 SVG로
2. **새 콜아웃·인용박스 만들지 말 것.** 위 컴포넌트 목록에 있는 서식만 사용.
   특히 세로줄 인용박스를 새로 만들지 말 것 (`.callout`은 이미 있는 것이라 재사용 OK)
3. **이미지는 항상 리사이즈.** 표시 폭의 2배까지, 사진은 JPEG 품질 78
4. **같은 스톡 사진을 한 사이트에서 재사용 금지.** 장부로 관리, 대체 없으면 사진 생략
5. **고객사 로고는 이미지만.** 사명 텍스트 노출 금지 (고객사 요청)

## 6. GEO 관련 구조 (콜비즈에서 검증된 것)

- `.answer` 박스 = AI 검색이 인용해가는 핵심. **각 페이지 최상단에 1개**, 질문에 대한 직답을 2~3문장
- `.faq details` = FAQPage 스키마와 세트로 넣음
- JSON-LD 2개를 head에 (`Organization` + `BreadcrumbList` 또는 `FAQPage`)
- 내부링크는 `.inlink` 클래스로 본문 안에 자연스럽게

## 7. 동적 렌더링 구조 (콜비즈에서 그대로 가져올 것)

```
functions/local/[[path]].js   ← Cloudflare Pages Function. /local/* 전부 처리
_local/engine.mjs             ← 데이터 + 렌더 함수 (459줄)
_local/dongs.mjs              ← 읍면동 데이터 (232줄)
```

engine.mjs 구성:
- `KEYWORDS[]` 키워드 정의 + `KW_ANGLE{}` 키워드별 고유 문단 + `KW_COURSE{}` 키워드 그룹별 본문
- `PROVINCES[]` 시도→시군구, `DONGS{}` 시군구→읍면동
- `renderCity()` / `renderDong()` / `renderProvinceHub()` / `renderNationalHub()`
- `page(d)` 공통 HTML 셸
- `provinceUrls()` / `allLocalUrls()` → 사이트맵을 **시도 단위로 분할** 생성
  (`/local/sitemap.xml`이 인덱스, `/local/sitemap-{시도}.xml`이 실제 URL)
- 캐시: `max-age=600, s-maxage=86400`

**비트웨이브 이식 시 바꿀 것**
- 키워드 축을 대표번호 → 콜센터·CRM·IPCC·AI로 교체 (콜비즈와 키워드 겹치면 안 됨)
- 업종 축(33개) 추가 → 지역×업종 조합 생성
- `SITE` 상수, 브랜드명, 전화번호, 푸터 정보 교체
